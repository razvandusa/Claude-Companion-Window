# Claude Companion

A floating macOS companion window for Claude, in the spirit of the ChatGPT macOS
companion window. Press **⌥Space** anywhere to drop a chat panel over whatever
you're doing; press it again to dismiss.

Replies run on your **Claude Pro/Max subscription** via the Claude Code CLI —
no API key, no per-token billing. See [Authentication](#authentication).

## Build and run

```sh
./Scripts/build-app.sh          # release build → build/ClaudeCompanion.app
open build/ClaudeCompanion.app
```

The app has no Dock icon (`LSUIElement`). It lives in the menu bar; the panel is
opened with the global shortcut or from the status item menu.

```sh
swift build     # compile only
swift test      # 84 unit tests
```

Requires macOS 14+, Xcode 16 (Swift 6 toolchain, Swift 5 language mode), and
Claude Code on the machine.

## Authentication

**Replies use your Claude subscription, not API credits.** There is no API key
anywhere in this app.

Every turn is generated by the [Claude Code](https://claude.com/claude-code) CLI
running headless, which authenticates with the OAuth login from `claude auth
login`. Prerequisites:

```sh
claude auth login     # Pro or Max account
claude auth status    # should print "authMethod": "claude.ai"
```

Settings shows the signed-in account and plan. Two details worth knowing:

- **`ANTHROPIC_API_KEY` is stripped from the CLI's environment.** Claude Code
  prefers an environment key over the OAuth login, so leaving one in scope would
  silently move usage back onto API credits — the exact thing this app exists to
  avoid. If Settings reports "billed to API credits", Claude Code itself is
  configured against a key; `claude auth login` fixes it.
- **The binary is found without a shell.** A `.app` is launched by `launchd` and
  inherits none of your shell's `PATH`, so the usual install locations are
  probed directly, then a login shell is asked as a fallback. Set an explicit
  path in Settings if you installed somewhere unusual.

Subscription rate limits (the 5-hour and weekly windows) surface as a banner
when the CLI reports them mid-turn.

## What's here

| Area | Notes |
| --- | --- |
| Window | `NSPanel`, `.floating`, joins all Spaces, appears over full-screen apps, rounded + `NSVisualEffectView` material, hides rather than closes, remembers frame |
| Dismissal | ESC (cancels a running response first, then dismisses), ⌘W, optional click-outside |
| Shortcut | `KeyboardShortcuts` by Sindre Sorhus, default ⌥Space, rebindable in Settings |
| Streaming | Newline-delimited JSON from a `claude` child process, `AsyncThrowingStream`, cancellable (cancelling terminates the process) |
| History | Held by Claude Code: the first turn creates a session, later turns `--resume` it, so only the new message crosses the pipe |
| Markdown | Headings, lists, quotes, tables, rules, fenced code — including unterminated fences so code renders while streaming |
| Code | Regex-driven highlighting for 20+ languages, language chip, copy button |
| Input | `NSTextView` composer: Return sends, Shift-Return newlines, grows to fit, paste images, drop files anywhere on the panel |
| Attachments | `+` menu: upload a file or photo, take a screenshot (selection / window / entire screen), take a photo with the camera |
| Web search | The globe grants the turn a single `WebSearch` tool; off by default |
| Work With | The apps glyph opens a searchable picker of running and installed apps; a picked app's front window is captured and attached at send time |
| Dictation | The mic transcribes into the composer with `SFSpeechRecognizer`, preserving whatever was already typed |
| Reply actions | Copy, read aloud, mark unhelpful, retry — always visible under an answer |
| Persistence | One JSON transcript per conversation under Application Support |

## Architecture

MVVM with constructor injection. `AppEnvironment` is the composition root;
every collaborator is a protocol so views and view models can be built against
doubles (`InMemoryConversationStore`, `PreviewClaudeService`).

```
Sources/ClaudeCompanion/
├── App/          ClaudeCompanionApp, AppDelegate, AppEnvironment
├── Models/       Conversation, Message, Attachment, ClaudeModel, TokenUsage,
│                 CompanionApp
├── Services/     ClaudeCodeService, ClaudeCodeProtocol, ClaudeCodeLocator,
│                 ClaudeCodeStatus, ClaudeCodeError, ConversationStore,
│                 SettingsStore, LoginItemService, ScreenCaptureService,
│                 CameraCaptureService, DictationService, SpeechReader
├── ViewModels/   ChatViewModel
├── Views/        RootView, ChatHeaderView, TranscriptView, MessageRowView,
│                 MarkdownContentView, CodeBlockView, ComposerView,
│                 ComposerControls, AppPickerView, GrowingTextEditor,
│                 AttachmentViews, SettingsView
└── Utilities/    CompanionPanel, PanelController, MarkdownParser,
                  SyntaxHighlighter, AttachmentLoader, Theme, VisualEffectView
```

The AppKit layer (`CompanionPanel`, `PanelController`) owns presentation;
`ChatViewModel` owns conversation state. Neither reaches into the other except
through `AppEnvironment`.

## Models and reasoning

Claude Opus (`claude-opus-5`), Sonnet (`claude-sonnet-5`) and Haiku
(`claude-haiku-4-5`), switchable from the header or Settings.

Reasoning appears in a collapsed disclosure above each reply. "Show thinking"
controls that disclosure; how much Claude actually reasons is set by Effort
(`--effort`, default `medium` — a better fit for a chat window than the CLI
default of `high`).

The window is a chat surface, not a coding agent: every turn runs with
`--strict-mcp-config` and `--disable-slash-commands`, under its own system
prompt in place of the Claude Code agent prompt, in a dedicated empty working
directory so no `CLAUDE.md` or project memory leaks in.

The tool list is `--tools ""` unless the user lights the globe in the composer,
which widens it to exactly `WebSearch` — nothing that reaches the filesystem or
the shell — and swaps in a system prompt that admits the tool exists, since
telling the model it has none is a reliable way to get a refusal to search.

## Notes

- **Ad-hoc signing.** `build-app.sh` signs with `-`, so the app's identity
  changes on every build. Sign with a Developer ID identity for a stable
  identity and for "Launch at login" to register reliably.
- **Permissions.** Screenshots and Work With captures need Screen Recording,
  the mic needs Microphone and Speech Recognition, and "Take photo" needs
  Camera. macOS asks the first time each is used; the usage strings live in
  `Resources/Info.plist`. Under ad-hoc signing the app's identity changes on
  every build, so a grant given to one build may have to be given again after
  the next one.
- **Screen capture shells out to `/usr/sbin/screencapture`** rather than using
  ScreenCaptureKit, which means the selection UI, the shutter and the
  permission prompt are the system's own. The panel takes itself off screen for
  the duration so it isn't in the shot.
- **"Take photo" has no viewfinder.** The camera is opened, given ~0.7s to
  settle, fired once and closed — holding a live preview open for as long as a
  floating panel is on screen isn't a trade worth making.
- **Attachments** are downscaled to 1568px on the long edge and re-encoded as
  PNG on import; text files are inlined up to 256 KB. Images reach the model as
  base64 `image` blocks written to the CLI's stdin.
- **Retry** re-sends the last user turn. If the failed attempt got far enough
  for Claude Code to record it, the session will hold that question twice —
  harmless, and preferable to dropping the retry.
- **Transcripts live in two places**: the app's own JSON under Application
  Support (what the UI renders) and Claude Code's session store (what `--resume`
  replays). Deleting conversations in Settings clears the former only.
